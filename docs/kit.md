# Benchmark kit: compare private data against the public reference, locally

**What it does:** runs the same locked recipe on your dataset that was run on 250+ public patients, then writes one HTML page that puts your patients next to the public ones, claim by claim, each with its control. Nothing leaves the machine. There are no network calls, no AI, and no telemetry.

## Use
```
python -m bio.kit suggest my_cells.csv --dataset MY_COHORT > my.yaml   # 1. draft a manifest
#    2. open my.yaml and fix every line marked "# CHECK" (columns, pixel size, label -> role, markers)
python -m bio.kit check my.yaml                                         # 3. automatic checks
python -m bio.kit run my.yaml --out reports/MY_COHORT                   # 4. report
```
Outputs in `--out`:
- `report.html`: open in any browser; works offline.
- `patients_full.csv`: per-patient results with your real patient IDs. **Keep it local.**
- `share_summary.csv`: the same numbers with each patient replaced by a random code, and no cell-level data. Share it only if you choose to.
- To see a kit run next to the public data, open the browser page and drop `share_summary.csv` (or `patients_full.csv`) on it: it is listed as "kit results" and nothing is recomputed.
- `patient_key_KEEP_PRIVATE.csv`: which code is which patient. **Keep it local.**

## Input
One row per cell with these columns: patient, image/field, x, y, cell-type label, plus marker intensities (protein) or an AnnData `.h5ad` with counts (RNA). The manifest maps your labels onto roles: `T, neut, mac, B, stroma, tumor, other, drop`.
- **Private-only roles:** declare them with `extra_roles: {pmn_mdsc: neut}`. The report shows each one beside its nearest public proxy and never pools them.
- **Private-only T states:** add them under `extra_states: [lmp]`, with a matching `states:` entry pointing to the column.

## Checks (a failed check blocks the run unless `--force`, and the report flags forced runs)
- Cell spacing 4–15 µm after applying `pixel_size_um`. This catches pixel/µm mistakes.
- Enough cells per role (≥300).
- Each role's own marker is clearly higher in that role than in T cells. This catches wrong labels or wrong markers; it already caught vimentin as a bad stroma marker in CODEX.
- Which T-state markers are available, and the number of patients.

## Recipe
Locked v2p (`src/bio/recipe_protein.py`, `docs/recipe.md`): 10 µm = touching, 30 µm = nearby, shuffle null within each image, protein levels as within-image percentiles, one value per patient.

## Reference (`src/bio/kit/reference/`)
Per-patient summary tables from IMMUcan (179 patients), CODEX CRC (35) and SPATCH (3 patients, 4 runs). Sources and licenses are in `SOURCES.html`. Rebuild with `python -m bio.kit build-reference kit_manifests/*.yaml`.

## Xenium bundles
Public Xenium tumor data (10x demo datasets, Zenodo cohorts) comes as an "outs" folder with no cell-type labels. One command reads it, labels the cells from marker genes, and writes a draft manifest:

```
python -m bio.kit xenium <outs_folder_or_h5ad> [<more bundles>] --dataset NAME --out DIR [--patient ID | --patient-from parent|dirname]
                         [--areas CSV ...] [--clusters CSV|none ...] [--jobs N] [--resume] [--no-keep-parts]
python -m bio.kit check DIR/NAME.yaml        # after reviewing the roles and the report
python -m bio.kit run DIR/NAME.yaml --out reports/NAME
```
- **Needs** `cell_feature_matrix.h5` (the HDF5 matrix, not the zarr one) plus `cells.csv.gz` or `cells.parquet` in the folder (or its `outs/` subfolder). Coordinates are used as µm. An `.h5ad` with `obsm["spatial"]` and raw counts in X is also accepted.
- **Writes** `DIR/NAME.h5ad` (obs: `annotation`, `patient`, `sample`), `DIR/NAME_annotation_report.txt` and `DIR/NAME.yaml` (and the per-section parts in `DIR/parts/NAME/`, see `--jobs` below). One bundle is one patient (`--patient`, default NAME).
- **Cohorts: pass several bundles in one command**, e.g. `python -m bio.kit xenium data/crc/P01/outs data/crc/P02/outs --dataset XEN_CRC --out data/crc/kit`. Each bundle is read and labelled separately (own negative-control background and own specificity table), then stacked into one h5ad. The patient (and `obs["sample"]`) is the last folder name that is not `outs` (`--patient-from parent`, default) or the final folder name exactly (`dirname`); duplicates are refused and `--patient` is refused. Genes are the union of the panels (a gene missing from one panel is 0 there; this is warned and written into the report). The manifest reads `patient` and `field` from the obs columns `patient` / `sample`. The report has one block per section and a pooled cohort block. The manifest `path` is relative to the folder you ran the command in, so run `check` and `run` from the same folder.
- **How cells are labelled** (`src/bio/annotate.py`, `annotate(adata, method="auto"|"cluster"|"cell")`). Two methods; `auto` (the default) uses the cluster method when the bundle has 10x clusters and the cell method otherwise.
  - **Cluster method** (sparse panels, e.g. 380 genes: single cells carry too few counts for per-cell scoring). `read_bundle` loads `analysis/clustering/gene_expression_graphclust/clusters.csv` (`Barcode,Cluster`) into `obs["cluster_10x"]` when it is there (the kmeans files are not used). For each cluster and lineage, m = the mean per-1000-count expression of the lineage's marker set over the cluster's cells, and scaled = m / the reference maximum of that lineage, so every present lineage has a cluster at about 1.0 however common it is (a section that is 96% epithelium is fine). The reference maximum (and the per-marker maxima used below) is taken only over clusters with at least max(50, 0.5% of the section's non-LowCount cells) cells, so a handful-cell outlier cluster with an extreme value cannot become the 1.0 that every real cluster is scaled against (this had left two tumour-core sections with 1 Epithelial cell and 46k-75k Ambiguous). Clusters under the size rule are still labelled, scaled against the same reference, and their scaled value is shown as the true ratio, so it can exceed 1.0. If no cluster meets the size rule, all clusters are the reference. One addition to your rule: a lineage that is below its absent floor in every eligible cluster but present in a small cluster (a rare cell type that only forms small clusters) takes its reference from all clusters, so it is not lost as absent; the section's params record `reference` = {min_n, n_reference_clusters, n_clusters, fallback_all, fallback_lineages} and the report's method text states the rule. A cluster is called lineage L when L has the highest scaled value, scaled >= 0.4, m is above the lineage's floor (from the negative controls), at least 2 of L's markers (or the single specific marker) each have a cluster mean >= 0.5 x that marker's largest cluster mean (a lineage with exactly 2 markers in the panel, e.g. Plasma, needs both at >= 0.3 x), and the runner-up's scaled value is < 0.75 x the best (T/NK and Macrophage/Monocyte/DC do not count against each other); otherwise `Ambiguous`. A would-be tie is broken by the per-cell scoring: if the share of the cluster's cells in which the best lineage fires is >= 1.5x the runner-up's, the best lineage is called (cluster note `tiebreak: fired`); otherwise it stays a tie. A lineage whose largest cluster mean is below 2 x its floor is absent from that section and is never called (the report lists it). NK vs T: a cluster whose T scaled value is >= 0.5 x its NK scaled value is T, not NK (cytotoxic CD8 T cells express GNLY); NK also needs 2 enriched markers among NCAM1, KLRD1, KLRF1, NCR1 (GNLY does not count). T subsets are decided per cell, not per cluster: the cluster decides "T" (cluster label `T`), then each non-LowCount cell in it is Treg if FOXP3 count >= 2 and CD8A+CD8B = 0 (panels without FOXP3: IL2RA >= 2 and CTLA4 >= 2, same CD8 exclusion), else CD8T if CD8A+CD8B counts > CD4 counts, else CD4T if CD4 > CD8A+CD8B, else `T` (subset unknown: no evidence, or CD4 = CD8A+CD8B). A section with one mixed T cluster therefore gets all four labels. The cluster table shows the split of each T cluster; the report states how many T cells have no subset evidence (`t_no_subset` in the params). One FOXP3 count is treated as background (it was 50k Tregs vs 42k CD4T on the Marteau Xenium panel under the old >= 1 rule, half of them with exactly 1 count and 16% with CD8A); treat the subset split as soft. (The cell method uses the same per-cell rule, the same function.) `T` is a label with role `T` (plain T, no subset) in the draft manifest, in `LABELS`, and in the recipe's T types. Cells inherit the label of their cluster. Cells under 20 counts are `LowCount` and are left out of the cluster means. Cells the clusters file does not list (2-8% in the Marteau regions) are `Unclustered` (role `other`); they are counted in the report and not labelled cell by cell. Because scaling is per lineage, a cluster that mixes two lineages can still be called the stronger one when it has well over 1.33x the other's scaled value; check the Clusters table.
  - **Cell method**: per cell and lineage, the marker counts present in the panel are summed per 1000 counts and compared with a floor: max(3 x the negative-control probe rate, 1 per 1000). The lineage needs at least 2 markers detected (T also needs a CD3 gene). The highest ratio wins. Cells whose runner-up is within 75% of the best, or where nothing fires, are `Ambiguous`; cells under 20 counts are `LowCount`. T cells get the same per-cell subset rule as the cluster method: Treg (FOXP3 count >= 2 and no CD8A/CD8B; panels without FOXP3: IL2RA >= 2 and CTLA4 >= 2), else CD8T (CD8A+CD8B above CD4), else CD4T (CD4 above CD8), else plain `T` (no subset evidence).
  - **Plasma** uses JCHAIN and MZB1 only (both must be detected per cell, both enriched per cluster). SDC1 and XBP1 are not used: epithelium and many other cells express them.
- **`--clusters`**: one `clusters.csv` per bundle, in bundle order (like `--areas`); `none` = no clusters for that bundle, labelled cell by cell. Without `--clusters`, each bundle's own graphclust file is used if present (bundles with no `analysis/` folder fall back to the cell method; a file that matches none of the cells is skipped with a warning, an explicit one is an error). 10x computed the clusters per slide; slides are cut by `--areas` afterwards and the clusters are then evaluated inside each cut section. In the cohort h5ad `cluster_10x` ids are per slide (`""` = no clusters for that section).
- **`--jobs N`, sections, parts, `--resume`.** The run has two stages. Stage A reads each region (or `.h5ad`) and cuts it into sections; it uses at most `min(N, 3)` workers because a region can hold 1M cells, and writes one raw per-section file under `<out>/parts/<dataset>/raw/`. Stage B annotates the sections in `N` worker processes (spawn), **largest section first**, so one big slide no longer sets the wall time while small regions wait; each section is annotated exactly as in a serial run (own background, thresholds and clusters cut with the section). One line per finished section goes to stderr: `done <section>: <cells> cells, <s> s [i/n]`. The main process then reads the finished sections and assembles the cohort in samplesheet / section order, so the h5ad, report and manifest are identical for any `--jobs` and any completion order (tested: `--jobs 1` vs `--jobs 3`). Default `N` = `max(1, CPUs - 1)`; N is capped at the CPU count. **Memory:** a stage-B worker needs about 1 GB per 200k cells of its section (a 1M-cell section about 5 GB), plus the stacked cohort in the main process at the end; stage A holds one whole region (up to about 3 GB per 1M cells) in each of up to 3 workers. On a small-memory machine pass a lower `--jobs`.
  - **Parts:** each annotated section is kept as `<out>/parts/<dataset>/<section>.h5ad` (annotation, no patient columns) plus `<section>.txt` (its report; the first line is a `# part-key` fingerprint). Both are written under a temporary name and renamed, the `.txt` last, so a killed run never leaves a half-written part. The cohort is always assembled from the part files, which is why a resumed run gives the same bytes as a fresh one. The parts take about as much disk as the cohort h5ad; `--no-keep-parts` deletes them (and the `parts` folder) after a successful run. On a failure they stay, and the message says where.
  - **`--resume`:** a section whose two part files exist and whose key matches (same bundle files, areas file, clusters file, `--min-counts`, section name, and the same labelling / reading code) is not recomputed (`kept <section> (from parts) [i/n]`), and a region whose sections are all complete parts is not read or cut again (`skip cutting <region>`). Changing any of those inputs, or `src/bio/annotate.py` / `xenium.py`, silently invalidates the parts, so a stale part is never reused. Use it after an interruption or to rerun the assembly (e.g. after deleting the cohort outputs) without redoing the 1M-cell annotation.
- **The report** lists label counts, a Clusters table (cluster id, cells, label, best scaled value, top three scaled lineage values; cluster method), the markers used and missing from the panel, and a marker-leakage table (per-cell firing of each lineage's markers inside each label). Unreliable flag: with the cell method, a lineage firing in more than 10% of cells of 3 or more other labels (the CosMx 6K neutrophil problem); with the cluster method, a lineage whose clusters have a median (best minus runner-up scaled value) below 0.25. The draft manifest keeps its role and adds a warning, so read the report before trusting any test that uses it.

Caveats
- **No malignant-versus-normal call.** `Epithelial` becomes the `tumor` role, so on whole sections it includes normal epithelium and the "nest" is epithelium-dominated.
- **Slides with several patients: cut by sample areas.** A deposit's `<region>_coordinates.csv` (`Selection,X,Y`, polygon vertices in µm, the frame of the cell centroids) says which patient each part of the slide is. `--areas` (one file per bundle, same order, `none` = take that bundle whole) puts every cell into the selection polygon that holds its centroid, drops cells outside every polygon (the count is in the report and the manifest comments), and makes each selection one section named after the selection. `python -m bio.kit xenium data/marteau_crc/xenium/slide1_region1 --areas data/marteau_crc/xenium/slide1_region1_coordinates.csv --dataset M_S1 --out data/marteau_crc/kit` cuts one slide; `python -m bio.kit xenium --samplesheet data/marteau_crc/xenium/samplesheet.csv --dataset MARTEAU_XENIUM --out data/marteau_crc/kit` runs a whole deposit (`--regions R1 R2` for a subset). Give `--areas` after the bundles. A whole deposit with its clusters and 8 workers: `python -m bio.kit xenium --samplesheet data/marteau_crc/xenium/samplesheet.csv --dataset MARTEAU_XENIUM --out data/marteau_crc/kit --jobs 8 --resume` (each region's own graphclust file is picked up automatically).
- **Section names:** `obs["patient"]` is the full section name (run1_crc_b_m), so core, margin and normal sections stay separate images. Two more columns are written: `tissue` (`_c` core, `_m` margin, `_n` normal, else unknown) and `patient_id` (the name without the suffix, run1_crc_b, to link the sections of one patient). The suffix meaning is our reading of the names; the deposit does not state it.
- **Labels are marker calls.** Xenium panels are small: a lineage with fewer than 2 markers in the panel cannot be called (listed in the report), unless its single marker is specific (EPCAM epithelial, PECAM1 endothelial, MYH11 or ACTA2 smooth muscle / myofibroblasts, MS4A1 B, CPA3 mast): then it is called from that marker with at least 2 counts, and the report says so. Plasma ignores immunoglobulin genes (IGKC, IGHG*, IGHA*, IGLC*), which are ambient in tumour tissue, and the CD4T/CD8T split is soft because CD4 and CD8 are lowly detected (the report says how many T cells have no subset evidence and are labelled T). Ambient RNA and segmentation spill-over put lineage markers into neighbouring cells; the marker-leakage table is the check.
- `Unclustered`, `Ambiguous` and `LowCount` map to role `other`, not `drop`, so they still count as cells in density and compartment calculations.
- The T-subset roles (`T:CD8`, `T:CD4`, `T:Treg`) and `mac_states` / `mac_identity_genes` need the recipe v3p changes (`docs/recipe-v3.md`); until they land, `check` rejects the manifest as an unknown role.


## Not yet supported
- HALO object-data export importer (needs a sample file).
- Steinbock/Hyperion folders (convert to CSV or h5ad first).

## Browser version (no setup): Tumor Neighborhood Benchmark
- **Standalone file:** `web/dist/tumor-neighborhood-benchmark.html` (6.6 MB). Opens from disk in any browser and works offline. Its Content-Security-Policy blocks every network request, so the browser itself prevents data from leaving.
- **Hosted:** https://runtkee.github.io/tumor-neighborhood-benchmark/ (the same standalone file, served by GitHub Pages from `docs/index.html`). Computation stays local to the viewer's browser.
- Source: `web/recipe.js` (port of recipe v3p, spec in `docs/recipe-v3.md`), `web/app.js`, `web/app.css`, `web/body.html`. Build with `uv run python web/build.py`; it writes `docs/index.html`.
- **Parity:** `analysis/parity_check.py <manifest>` runs Python and JS on the same CSV. CODEX (1,311 values) and IMMUcan (5,655 values) match to ≤1e-12. `tests/test_parity.py` keeps them in sync.
- **v3p in the browser:** the importer reads `T:CD8` / `T:CD4` / `T:Treg` role values (T subset), `mac_states` (macrophage markers, `macstate_<name>` columns) and `columns.compartment` + `compartments` (annotation). Without an annotation, compartments are computed per image from cell positions with the same inclusive rules as `src/bio/compartment.py`. The v3p pass (composition, nest proximity with the compartment-stratified shuffle, distance gradient, nest contact tests, macrophage state next to T cells) is a line-by-line port of `_v3p` in `src/bio/recipe_protein.py`, built on typed-array grids so it stays linear in the number of cells. On 2 million cells it adds about 8 s (2.7 s compartments, 5.7 s the pass) to about 13 s for the v2p.1 part.
- **v3p parity:** `tests/test_parity.py` compares every per-patient column (legacy and v3p) between Python and JS to 1e-9 on the synthetic sets (subsets, macrophage states, an image without tumor cells, an annotation column) and on the 3-patient CODEX fixture with the reviewed manifest. Observed max difference about 4e-13.
- CSV input and the protein recipe only. RNA data stays with the Python kit.
- Mapping is automatic (`web/automap.js`) and read-only; see README "How files are read". The Python kit keeps reviewed manifests for the reference datasets.

## Validation and size (browser version)
- `runChecks` in `web/recipe.js` returns `[check, pass|warn|fail, what we found, how to fix]`. Any fail blocks the comparison unless the user forces it, and forced runs are flagged on the results.
- The loader streams files (`importFiles`), stores coordinates and readouts in typed arrays, and interns repeated strings.
- An image is identified by patient plus image name, so names reused across patients ("Core 1") stay separate. The Python kit applies the same rule.
- Readouts with fewer than two distinct values are left out in both versions.
- New checks in v3p: `tumor cells` (warn when no label maps to tumor), `nest size` (warn under 20% of cells or 300 nest T cells), `T subsets`.
- Tests: `node tests/test_validation.js` (parser chunking, streaming vs whole-file, 13 bad-data cases), `node tests/browser_smoke.js docs/index.html [files]`.
